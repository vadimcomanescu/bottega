# A question the user cannot judge produces answers that mean nothing

What happened: in a 2026-07-27 guru run on nadia-core, discovery's interview asked the user to choose between CI shapes using names the run had coined while exploring ("the JS check lane", "the gate matrix leg"), with the tradeoff compressed into the question's option labels. The user answered five times that they did not understand and asked for a junior-level explanation with concrete examples; each re-ask came back shorter, not fuller, because the question format rewards compression and nothing told the run that "I don't understand" means the explanation was missing. The interview stalled and settled nothing.

The rule: every interview question stands on an explanation given in the same message, in the product's own words with a concrete example (what exists today, what each answer would change, what it would cost), and a term the run coined while exploring is explained before it is used. "I don't understand" means explain fuller and ask again, never shorter. The user's stated starting point, asked for at Explore, sets how much each question must explain.

Enforced: skills/interview-and-capture/SKILL.md (the explanation rule and the starting-point question).
