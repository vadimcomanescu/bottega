# A verifier reviewed without its threat model never converges

What happened: on 2026-07-28 a maestro run took nadicodeai issue #623, a worktree setup script that never built a workspace package while its readiness check said ready. The complete fix was green three hours in at 367 insertions. Five review cycles followed (bottega issue #172). Each cycle found one more hand-crafted symlink layout that fooled the new check, each finding was real and reproducible by constructing the state, and seven fix commits grew the branch to 1,230 insertions, 863 of them armor and tests against layouts no one had ever produced by accident. The two-cycle pause fired and changed nothing, because the classification had no axis on which a real, reproducible finding could still be not-work: every symlink escape read as a concrete security exposure, the one exception that authorizes blowing up scope. The owner ended it with one sentence, the check answers for accidents and not for crafted layouts, and the branch was reverted to the original fix.

The rule: work that adds a check, a gate, or a validator declares its threat model in the design, one sentence naming what it must catch and what it deliberately does not, and ships it with the check. The review prompt carries that sentence, and a finding whose failure scenario requires an actor outside it is rejected by rule, however good its repro. A constructed repro proves reachability by an attacker, not by an accident.

Enforced: skills/maestro/SKILL.md (the design's threat-model sentence, the maestro ruling on findings, the two-cycle stop to the owner), skills/code-review/SKILL.md (threat model in the frozen baseline and the review prompt, the out-of-threat-model class, computed growth numbers, the narrowing requirement after the two-cycle pause).
