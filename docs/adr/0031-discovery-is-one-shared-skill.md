# Discovery is one shared skill, and every question carries its explanation

Guru carried its own discovery paragraph while maestro routed to `bottega:discover`, and the two drifted in both directions. Guru's copy held the working sweep (cheap workers fanned out to read prior art and the installed versions' own docs and source) that the shared skill reached only through a worker-table indirection at medium effort; the shared skill held the brainstorm, prototype, and reference moves guru's compressed copy dropped. Continuing ADR 0030's line, guru now routes its discovery to `bottega:discover`, the same skill maestro's Discover phase uses, and keeps standalone only what is its own: the contract, the briefs, the drives, and the looped review. The sweep's mechanics move into the shared skill in guru's own words, with the explorer row's effort lowered to match: the sweep is wide because each worker is cheap.

The same change fixes an observed interview failure (docs/lessons/questions-carry-their-explanation.md): the interview step now requires every question to stand on an explanation given in the same message, in the product's words with a concrete example, and defines "I don't understand" as a missing explanation, answered by explaining fuller, never by re-asking shorter. The blind spot pass and the interview no longer hang on entry conditions; the starting-point question at Explore calibrates how much every later step must explain, which is the field guide's own mechanism.
