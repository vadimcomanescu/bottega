# Guru routes its opening and closing to the shared skills

ADR 0026 made guru one standalone prompt with `bottega:panel` its only skill route. That put the run's opening and closing mechanics (worktree and branch, owner file, release answer, hold label, arming, the check watch) into guru's own text as near-verbatim copies of `bottega:open` and `bottega:close`, and the copies drifted: guru's opening never said to enter the worktree it created, so a guru run could work from the user's main checkout. The mechanics are not what guru exists to carry. Guru is the discovery, the contract, and the delivery middle; the opening and closing are the same for every run.

Guru now routes its opening to `bottega:open` and its delivery to `bottega:close`, the same skills maestro's Launch and Close phases use, and keeps standalone only what is its own: the grounding, the interview, the run contract, the builder briefs, the drives, and the looped review. The two shared skills were made caller-neutral in the same change: `open` records the release answer the launch settled, whichever entry point settled it, and `close` routes a repairable red through the run's repair path, whichever run defines it. `open` also states the entering plainly, because the drift showed the old wording ("make it your working directory") did not land: create the worktree and enter it, and every command for the rest of the run runs from inside it.

The model-naming exemption of ADR 0026 stands: guru's middle still names its workers' models where it dispatches them, because a standalone prompt cannot resolve a worker-table row.
