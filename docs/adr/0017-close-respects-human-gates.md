# 0017: Close respects the gates it cannot clear

Date: 2026-07-24

ADR 0016 made the run merge its own PR but left close with one terminal state (merged) and two readings of a red check: the diff caused it, or infrastructure did. A check only a person can clear fits neither, so close could not exit and would send a builder at a failure no code change fixes; the case that showed it is a repository whose `review-labels.yml` stays red until a human adds a `ci-reviewed` label to a PR touching CI-sensitive paths. Close now has a third reading and a second terminal state: a required human review, a human-added label, or any other approval no code change satisfies stops close, which reports what is needed and on which PR and leaves the PR open and unmerged, and the run never satisfies such a requirement itself, because doing so defeats the check it stands for. The same change makes two parts of 0016 real. The merge pins the head phase 1 confirmed (`--match-head-commit`), so the head that carried the evidence is the head that lands. Branch protection under a strict policy (required checks not up to date with the base) is answered with `gh pr update-branch`, a fresh check watch, and a merge when they go green, with any other platform refusal reported verbatim as before. The vendored autoreview document's merge rule, which forbade any merge the user had not armed in their own words, is scoped to a standalone `bottega:autoreview`, where no run gates the merge; inside a run the recorded evidence is that gate and close merges on it.
