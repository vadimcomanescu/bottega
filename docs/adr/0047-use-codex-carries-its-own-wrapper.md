# Codex dispatches run through the skill's own wrapper

Date: 2026-08-08.

ADR 0038 vendored OpenAI's codex plugin as the dispatch runtime, and ADR 0043 gathered it into `vendor/codex/`. That bought receipts, a status watch, pinned resume, and cancel, and it cost a standing machine: an app-server driven through a broker daemon, SessionStart and SessionEnd hooks to stamp session ids and tear the broker down, a vendored agent file as the forwarder, and a sync contract over twenty-three files. The machine also bound codex dispatches to the plugin install: skills distributed as plain files into a repository arrived without the runtime, the hooks, or the agent, so the codex seats only worked where the plugin was installed.

Two facts retired the trade. The codex CLI now carries the mechanics the vendored runtime wrapped: `codex exec` takes the model, the effort as a config override, the sandbox policy, the working directory, and `--output-last-message` for a clean report, and `codex exec resume <session-id>` continues a thread. And the forwarder agent was one rule, make one Bash call and return its stdout, which a generic subagent executes from its dispatch prompt.

Decision: codex dispatches run through `skills/use-codex/scripts/codex-task`, bottega's own wrapper over `codex exec`. One detached codex process per job, job state as plain files per workspace under the machine's state directory, receipts, `status --wait`, `result`, `cancel`, and resume with the job's recorded model, effort, and sandbox replayed. The wrapper refuses a task missing `--model` or `--effort`, so the pin rule lives in the interface. A job runs unsandboxed by default, and `--read-only` is the one restriction, the contract a review seat carries: a read-only job provably left the tree it judged untouched. The dispatch is a sonnet subagent forwarding one call, per the skill's own instruction block. `vendor/codex/` is removed whole, the SessionStart and SessionEnd registrations with it, and nothing codex remains in `THIRD_PARTY.md`.

This supersedes ADR 0038 and ADR 0043, and ADR 0039's subject no longer exists. What 0038 fixed stays fixed and is pinned by `tests/codex-task.test.ts`: the orchestrator's turn holds only the tracked `status --wait`, a resume never falls back to the machine's defaults, liveness is the job's recorded state, and `cancel` kills a run judged stalled. What 0038 accepted as hygiene is now structural: there is no daemon to tear down, so nothing lingers after a session, and the one remaining duty is the skill's own rule to cancel every receipt the orchestrator stops watching, because a running job outlives the session that started it.

Consequences. Jobs survive sessions on purpose: a later session continues an interrupted watch with the same status, result, and resume calls, which retires 0038's rule that work crossing sessions needs a fresh dispatch carrying the old report. The route guard reads `codex-task task` and raw `codex exec` commands for the model pin, and the `bottega:codex` pass is gone with the agent. The skill and its wrapper travel together as one directory, so a file-based install of the skills carries the whole codex mechanic, and the only host requirement left is the codex CLI, logged in.
