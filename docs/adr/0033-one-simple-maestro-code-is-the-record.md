# One simple maestro; the code is the truth and the PR is the record

The owner set the direction on 2026-07-28: the run reads as one person briefing a capable colleague, and the work's agreement lives in the conversation, not in committed documents. Maestro is rewritten to one simple flow: launch (the release answer, then the orchestrator-model check), discovery with the user, the design made and owned by the orchestrator, one codex second opinion, builders fanned out with per-slice reviewers, the integrated review, a QA drive looped until every scenario passes, and close.

Deleted with their producers: the spec and plan skills and the committed `docs/specs/` and `docs/plans/` directories (git history holds the delivered ones), the guru entry point (the new maestro is that method, so a second entry point saying the same thing is drift waiting to happen), the build skill (the flow's build paragraph carries it), the spec-conformance check (with no committed spec its input is gone; measurable acceptance criteria and the QA loop absorb its job), and the worker table with its ADR 0025 rationale.

What replaces the documents. Discovery's artifacts (approved prototypes, decisions, references) stay with the run while it builds and never merge, because a committed prototype outlives its purpose and gets read as precedent by later runs. What must outlive the run lands where it is enforced or read: an enforceable acceptance criterion becomes a test, a decision that is hard to reverse, surprising without context, and a real trade-off becomes an ADR in the same diff (a reversal naming the verdict it reverses, per the supersession lesson), an operating fact goes to the agent map, and the PR body carries the rest. The plan editor's rewrite-whole contract is replaced by the second opinion's maintainer bar: revise only where a strong maintainer, seeing both the current plan and the proposed change, would clearly agree the revision is necessary or materially better; otherwise the plan is ready.

Worker models are named in the sentences that dispatch them: Claude workers on opus-5, the second opinion on gpt-5.6-sol at high effort, the panel's seats and the vendored engine's models in their own files. Effort disappears from every Claude dispatch because the harness cannot apply it there: the Agent tool's dispatch parameters carry a model and no effort field (read from the harness documentation and the tool schema on 2026-07-28; effort exists only as agent-definition frontmatter, and bottega ships no agent definitions), so five of the seven table rows carried a value nothing could apply. The route guard is unchanged in policy: a live run's dispatch names a model, and fable is never a worker.

Supersedes ADR 0025 (the one worker table; its condition, twelve scattered pin sentences, no longer exists and its Claude rows had collapsed to one value), ADR 0026, 0030, and 0031's guru clauses (guru is deleted; discovery remains one shared skill), ADR 0004 and 0007 (no committed specs), and amends ADR 0032: codex's sites are now the second opinion, the review's GPT engine, and the panel's seat, with the same Opus-at-same-contract fallback when the CLI is unavailable.
