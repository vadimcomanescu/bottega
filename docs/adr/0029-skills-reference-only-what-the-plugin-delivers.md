# 0029: Skills reference only what the plugin delivers

Date: 2026-07-27

Every skill under `skills/` is self-contained, or it references content the plugin delivers. The forcing fact is the install: an installed plugin cannot reference files outside its own directory, and those external files are not copied to the cache, so the cache copy is the consumer's whole world. A path a skill names therefore either resolves inside `skills/`, names a component the plugin ships (the `hooks/` guard), or names a file of the host repository the run works on, which is instruction about that repository rather than a reference to bottega's. Nine citations of bottega ADRs, lessons, and research notes had accumulated across seven skills, two of them rules a run actually depends on, and a worker following those pointers on a consumer's machine finds nothing at the path.

The rule has two halves, and the second is the one that changes how skills are written. Bottega's internal record (`docs/adr/`, `docs/lessons/`, `docs/specs/`, `docs/plans/`, `REVIEW.md`, `tests/`, `THIRD_PARTY.md`) documents this repository for its maintainers and is never cited from a skill, so a rule a skill carries stands on its own sentences and the decision behind it stays in the repository record, uncited. Keeping the citations was rejected: they resolve today only because a development checkout happens to hold the skills and the record under one root, which is incidental to how the tree is read and not something the install honors.
