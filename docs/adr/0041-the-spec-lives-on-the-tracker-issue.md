# 0041: The spec lives on the tracker issue

Date: 2026-07-31

Amended on 2026-08-07 by `0046-beads-is-the-tracker.md`: the surface is the run bead, not a tracker issue. The spec is written into that bead's design field rather than posted as a comment or a new issue body. The placement this record settled, out of the repository and on the run's own tracked unit of work, stands.

Supersedes 0033 in part. 0033 removed the spec skill and the repo's spec files and made the PR the record; its code-is-truth and PR-is-record halves stand. What returns is a spec written at the end of discovery as pure synthesis, published on the run's tracker issue: a comment when the run started from an issue, the body of a new issue otherwise, and that issue anchors the run. The repo stays free of spec files: the tracker carries the agreement, the PR carries the build. Prototypes follow the same surface, captured to a throwaway branch out of main with the pointer and verdict on the issue, so the primary source stays reachable after the run. The cost accepted is a second surface the run must keep true.
